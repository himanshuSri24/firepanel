Firepanel

A read-only Chrome extension that adds search and JSON copying to the Firebase Firestore console. This page explains how it works today — what runs, in what order, and where each decision lives in the code.

Primer: the unfamiliar words

Content script (Manifest V3)
A JavaScript file Chrome injects into matching web pages. It shares the page's DOM but not its JavaScript variables, and it runs with the extension's permissions rather than the page's. Firepanel is one content script and nothing else — no background worker, no popup.
Angular CDK virtual scroller
The mechanism the Firebase console uses to render long lists. Only the rows currently on screen exist in the DOM; scrolling swaps their contents. This is why a filter cannot simply read the list — most of it is not there to read.
__name__
Firestore's reserved field for a document's own ID. Queries can use it for range comparisons, which is what makes a prefix search possible — >= "p60" finds everything from that point on in ID order. Firestore has no substring operator on IDs, at any price.
Chrome Web Store review
A human and automated check before an extension is listed, focused on whether the requested permissions match the stated purpose and whether the listing implies affiliation with a platform it merely extends.

How it stays attached

The console is a single-page app that rebuilds its panels on every navigation, so injection is not a one-off. A watcher re-runs a sync on every DOM mutation it did not cause itself, on a one-second tick, and whenever the tab becomes visible. Each component decides for itself whether it still has work to do.

Why a plain tick rather than a clever event. The console repaints for reasons that are not observable from outside it — theme toggles rewrite styles rather than nodes, panels swap without navigation. Each component compares the surface it mounted against to what is painted now and rebuilds if they differ, so the sync only has to run often enough, not at exactly the right moment.

Copying a whole document

The console renders a map's or array's children only once that branch is open, so a copy of what is on screen would be a copy of whatever the user happened to expand. Firepanel opens every collapsed branch first.

What counts as a disclosure control

An element with aria-expanded="false", or failing that, a clickable element positioned to the left of the field key — where the console puts its chevron and never puts a row action. Anything labelled edit, delete, add or copy is excluded outright. A field whose control cannot be identified is skipped and counted, and the button says so rather than silently copying a partial document.

Finding a document the list will not load

A documents list stops accepting rows after a few hundred, so scrolling cannot reach an arbitrary ID. Firestore cannot match the middle of an ID at all. What it can do is a range over __name__, and the console's own query builder can express exactly that — and puts it in the URL.

Colour

The console ships light and dark themes and marks neither on the elements Firepanel injects into, so every colour is derived from what is actually painted behind the injection point.

Where data lives

Data Lifetime Leaves the browser?
Harvested list names In memory, per panel, cleared on remount No
Parsed document JSON Built on click, handed to the clipboard, discarded No
Resolved theme colours In memory, recomputed on remount No
Anything persisted There is none: no storage API, no cookies, no network calls of its own

Tests

The browser-dependent parts are verified by using the extension; what is testable without a browser is tested, and those are the parts where a silent mistake is expensive.

Test file Pins down
tests/query-view.test.ts The exact query string the console produces, length prefixes, nested scope paths, and that the page's project path survives
tests/theme.test.ts That the two entry points cannot recurse, that an unpainted element resolves to its painted ancestor, and that light and dark map to the right accent
tests/document-parser.test.ts Type casting, array ordering by numeric key, empty map versus empty array, and unwrapping stringified JSON without mangling text that merely looks like it

Build and release

Operating it

Situation What to do
A filter box stops appearing The console's markup moved. Every selector is in src/console-dom.ts.
Copy JSON reports "n not expanded" Run __firepanelDebug() in DevTools; it prints the markup of one collapsed field's click target.
Colours look wrong Run __firepanelTheme(); it prints the reference element, resolved surface and whether anything painted was found.
Nothing works at all Look for [Firepanel] in the page console. A startup throw is reported there rather than swallowed.
